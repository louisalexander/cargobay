# Cargo Bay v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An HAOS add-on that serves SpoolmanScale's Part 1 Inventory API from 3dfp (cached,
quota-safe), and binds scanned third-party spools to AMS trays through Home Assistant.

**Architecture:** One asyncio Python process: an aiohttp server for the scale (Part 1) and two
HA-callable bind routes; an aiohttp client to 3dfp; an aiohttp websocket client to HA core via
the Supervisor. SQLite holds only what 3dfp has no field for. Every 3dfp field name lives in one
module (`mapping.py`), pinned by a live capture in Task 1.

**Tech Stack:** Python 3.12, aiohttp 3.x, stdlib `sqlite3`, pytest + pytest-aiohttp, uv,
HA add-on base image `ghcr.io/home-assistant/{arch}-base-python:3.12-alpine3.20`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-20-cargobay-design.md` (approved 2026-11-21). Contract:
SpoolmanScale-Integration `inventory/spec.md` + `common.md` at commit
`73e8409dffc4f06b4168753e8ea2e16bbd16f50a`. Read both before Task 2.

**Scope:** spec milestones M1 (bridge against fakes, checker green in CI) and M2 (installed on
HAOS, live 3dfp + AMS). The HA side (§5.4 picker, `rest_command`s, automations, `docs/3d-printer.md`)
lives in `~/code/homeassistant` and gets its own plan after Task 11. M3 (hardware) is a manual
checklist, not tasks.

## Global Constraints

- SpoolmanScale firmware unmodified; Part 1 contract v1 only. §6.4/§6.5/§7.2 answer `404`.
- 3dfp quota 1,000 req/month, 4xx count, shared with `filament_sync.py`. **Never poll 3dfp.**
  `health`, `info`, list, stamp, single spool, scan, `field/spool`, `location`, `tag/reader`
  make **zero** 3dfp calls.
- 3dfp weight writes are absolute `remaining_grams` (rounded int). `0` triggers 3dfp's Empty.
- Slot location `"Printer: Bambu P2S, AMS: 1-<slot>"` (slot 1–4); shelf
  `"Shelf: Office Supply Closet"`; 3dfp reads null back as `"Shelf"`. On `invalid_location`
  for the shelf, retry once with `null`.
- 3dfp: base `https://3dfilamentprofiles.com/api/v1`, `Authorization: Bearer <key>`, quota left
  in response header `X-RateLimit-Remaining`, errors as `{"error": {"code", "message"}}`,
  `GET /my/spools` → `{"data": [...]}` and a hint of more pages (`next`, `has_more`,
  `total > len(data)`) is refused, never acted on.
- Key file is read, never copied, logged or committed. The repo is **public**: no captured 3dfp
  data, key, LAN IP or SSID is ever committed; fixtures are synthetic.
- Never touch a tray whose `tray_uuid` is real (non-empty and not all `0`).
- A binding comes only from scan-then-load or an explicit bind call. Never from colour/material.
- `unavailable`/`unknown` → loaded is not a load event.
- Port `7912/tcp`. Tray entities `sensor.laforge_ams_2_pro_tray_1..4`.
- HTTP rules for the scale: no redirects under `/api/v1`, no `204`, no compression, writes answer
  `200` with the spool, ids are ints 1..2147483647 never reused, tags normalised (hex only, upper).
- Conventional Commits; branch off `main`; commit per task.

## Decisions the spec left to the builder

- **D1 3dfp shapes** are recorded in `docs/superpowers/notes/3dfp-shapes.md` (Task 1, done).
  Only `mapping.py` knows them. Key facts: `rgb` is `#RRGGBB`; `location` `"Shelf"` means unset;
  no archived flag — Empty ⇔ `remaining_grams == 0`; `empty_spool_weight` is a per-spool tare;
  `spool_properties.bambu_tray_uuid` is in the list for paired Bambu reels; no net weight, no temps.
- **D2 Bambu reels without quota.** Tray UUID → spool comes from `Remote.bambu_tray_uuid` in the
  cached list. No per-spool detail GETs, no filament_sync cache file.
- **D3 "Bambu reel loaded"** (§5.2a 409) = some tray sensor's live real `tray_uuid` equals
  (normalised) this spool's `bambu_tray_uuid`.
- **D4 HA transport.** Websocket `ws://supervisor/core/websocket` for `get_states`,
  `subscribe_events` (`state_changed`), `call_service`, `fire_event`. Sensors are set over REST
  `POST http://supervisor/core/api/states/<entity_id>`. Both authenticate with `SUPERVISOR_TOKEN`.
- **D5 Quota.** Remaining = last `X-RateLimit-Remaining` seen (persisted with its month); fallback
  1000 minus own count this month. Below 100: fire `cargobay_quota_low {remaining}` once per month,
  stop refreshes, keep writes. The push itself is an HA automation (HA-side plan).
- **D6 Refresh never blocks the scale.** Refreshes run as a background task; requests answer from
  cache at once. One refresh at a time.
- **D7 Local-only spool fields:** `spool_weight` (tare), `initial_weight` override, `last_used`,
  `extra`, tags. Capacity/dates, not weight or location of record (anti-goal holds).
- **D8 Profiles.** Vendored `generic_profiles.json`, generated once from ha-bambulab's
  `filaments_detail.json` (Generic vendor entries). Lookup: exact `filament_type` match on the
  normalised material, preferring ids ending `99`; else match on its first token
  (`"PLA MATTE"`, `"PLA+"` → `PLA`). Overrides in options by `"<brand> <filament name>"`.
- **D9 Paths.** `map: [{type: homeassistant_config, read_only: true}]` mounts HA config at
  `/homeassistant`. Options default `key_file: /homeassistant/.3dfp_key`.
- **D10 Scale auth.** Accept `X-API-Key: <api_key>`, `Authorization: Bearer <api_key>`, or Basic
  with password `<api_key>` (any user). `GET /api/v1/health` is open. Else `401`.
- **D11 Multi-key PATCH** becomes **one** 3dfp PATCH (e.g. `remaining_grams` + `location`).
  A PATCH with only local keys makes no 3dfp call.
- **D12 3dfp failure on a write** → `502` `{"message": ...}`, local state unchanged. Cargo Bay's
  own refusals are `409`.

## Review Focus

1. **Quota leak via the scale's polling.** 30 s health poll for a month, plus the stamp before
   every list, plus a scan loop on an unknown tag every 4 s, must cost 0 3dfp requests beyond the
   ≤1 refresh per 10 min a scan miss may trigger. → Task 4 and Task 6 tests count fake-3dfp hits.
2. **Swap: weigh spool A just pulled from slot 2, then load B into slot 2 without scanning B.**
   Must fire `cargobay_unbound_load`, never bind A. → Task 8 test.
3. **3dfp down or 5xx during a write.** Scale must see a failed write (502), cache and SQLite
   unchanged, and the next GET shows the old weight. → Task 5 test.
4. **HA restart / websocket reconnect while trays are loaded.** Must not unbind, rebind or write
   3dfp; reconcile only. → Task 7 (reconnect) and Task 8 (reconcile) tests.
5. **A Bambu reel's tag scanned and weighed while it sits in an AMS slot.** Scan finds it (via
   `bambu_tray_uuid`), weight write answers 409 and makes no 3dfp call; the same reel on the shelf writes
   normally. → Task 5 test.
